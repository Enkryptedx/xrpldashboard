# Storage Inventory — 2026-05-25

Investigation-only audit per Task #4.1 prompt. Classifies every Postgres
table in Neon by history pattern and B2 backup coverage. Inventories
Mac-local JSON state. **No fixes proposed — just the map.**

Generated by querying production Neon on 2026-05-25 ~04:50 EDT.

---

## TL;DR

- **20 tables in Neon.** 9 capture history correctly. 5 overwrite-only
  (some data loss on every refresh). 4 singleton-overwrites where the
  history is preserved elsewhere. 2 static reference. 1 worker state.
- **B2 backup covers the filesystem only** (`~/xrpl_test/` → b2crypt remote
  via rclone). It does **NOT** dump Neon Postgres. The Neon database is
  protected only by Neon's own retention (free tier: 1 day PITR).
- **Three named real-time-only losses:** `token_prices` (daily prices),
  `amm_ranked_pools` (daily AMM rankings + TVL ordering),
  `credentials_snapshot` (daily credential set). All three are
  rebuildable from XRPL (slowly) but the as-of-yesterday view is
  unrecoverable today.
- **Mac-only state surviving on B2 backup:** historical_snapshots/ (14
  daily files), signed_snapshots/ (11 files), all root JSON cache files
  (amm_index.json, token_names.json, etc.). Safe as long as the Mac and
  B2 don't both die.

## 7. At-risk summary (the actual answer)

In priority order, the things that are at risk:

1. **Neon Postgres is not pg_dumped.** Single biggest exposure.
   Neon free tier = 1 day PITR. A bad migration, accidental drop,
   or Neon outage past 24h = total loss of 20 tables, including the
   correctly-historicized ones (amm_tvl_history, token_volume,
   unl_snapshots, etc.).

2. **Five overwrite-only tables lose daily snapshots.** Real but
   bounded — all five are rebuildable from XRPL or by re-running a
   walker. The "as of yesterday" view is lost. Worst offender is
   `token_prices` (no path to reconstruct a clean daily price series).

3. **historical_snapshots/ directory has only two copies (Mac + B2).**
   Not in Neon. If both Mac and B2 fail, the daily rollups May 7–25
   are gone forever.

4. **No `schema_version` columns on any table.** A future schema
   migration will need ad-hoc reasoning about what each row "means"
   based on insert-time inference.

5. **~/.ssh skip in B2 log** — worth confirming that's intentional
   (e.g., ~/.ssh doesn't exist on this Mac) vs. a misconfig.
