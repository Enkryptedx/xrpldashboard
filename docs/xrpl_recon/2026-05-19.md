## 4. Gap analysis — what xrpldashboard is missing

Ranked by editorial weight. Each gap is a concrete action.

### A. The biggest hole: no programmability story

XRPL is mid-transition from a fixed-grammar L1 to a programmable one — XLS-100
(Smart Escrows), XLS-101 (Smart Contracts), XLS-102 (WASM VM). None of this is
on xrpldashboard. This is the single largest narrative the dashboard does not
yet tell.

- **Proposed:** new page **`/smart-contracts`** (or `/programmability`). Three-act
  structure: (1) smart escrows as the first surface, (2) full smart contracts
  via ContractCreate/ContractCall, (3) WASM VM as the engine.
- Truth-first framing: this is roadmap, not shipping. Cite each XLS by number,
  link the standards page, mark each as Draft (not Final, not Activated).
- Editorial: this is the kind of page that gets shared the day an XRPL smart-
  contract rumour breaks. Build it before the news cycle, not after.

### B. Institutional privacy gap

XLS-96 (Confidential Transfers for MPTs) is the institutional privacy
primitive — EC-ElGamal + ZK proofs for hidden balances, total supply still
auditable. Banks and treasuries can't post payroll on a transparent ledger;
this is the fix.

- **Proposed:** section on **/institutional** (immediate) + future
  **/confidential-transfers** page if it gets a rippled PR. Pairs well with
  truth-first framing because public auditability is preserved.

### C. Wallet-security extension

XLS-86 (Firewall) — account-level outbound whitelist + fee limits, defeats
key-leak drain attacks. Slots directly into the wallet-page-as-integrity-check
framing.

- **Proposed:** "what's coming" callout on **/wallet/<addr>**. Doesn't need its
  own page until rippled PR lands.

### D. Forward-looking issuer compliance

XLS-73 (AMMClawback), XLS-82 (MPT in DEX), XLS-98 (Vault metadata schema) —
three issuer-side primitives that change the RWA / pools story.

- **Proposed:** section under **/pools** + **/rwa**.
